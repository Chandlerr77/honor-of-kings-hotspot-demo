# 游戏热点营销工作台

按游戏跟踪游戏圈热点，为每款游戏出抖音营销脚本。流程：**采集 → 核验 → 匹配与爆点拆解 → 生成 → 人工审核**。

## 跟踪的游戏

每款游戏一个配置文件，放在 `games/` 目录：

| 文件 | 游戏 |
| --- | --- |
| `games/wzry.json` | 王者荣耀 |
| `games/hpjy.json` | 和平精英 |
| `games/ys.json` | 原神 |
| `games/jcc.json` | 金铲铲之战 |

配置内容包括：设定与世界观、受众、调性、适合跟进的内容、这款游戏特有的禁忌、识别热点用的关键词、Apify 搜索词、脚本必带的话题标签。

**新增一款游戏**：复制一个文件，改好内容即可，代码不用动。所有游戏共用的规则写在 `rules.json`：抖音平台要求、通用禁忌、限制词、来源黑名单。

每条热点都会归到一款游戏下。核验、匹配和写稿都使用这款游戏自己的设定；页面顶部可以按游戏切换。

## 热点来源

| 来源 | 频率 | 说明 |
| --- | --- | --- |
| 上榜词条 | 每小时，免费 | 微博热搜、抖音热榜、B站热门中提到任一款游戏的条目，按关键词归到对应游戏。它们是破圈的游戏话题，热度由平台背书 |
| 游戏圈作品 | 每 2 天一次（北京时间 10:17），Apify 计费 | 一次运行同时搜索所有游戏，结果按搜索词归到对应游戏，内容还需命中这款游戏的任一关键词。抖音要求播放 ≥10 万；拿不到播放量时（Apify 免费版只返回样本）改为点赞 ≥1 万且评论 ≥100。小红书不公开播放量，按点赞 ≥1000 且评论 ≥50 判断 |

所有来源都经过黑名单过滤（`rules.json` 的 `blocklist`）：账号交易、代练、外挂等推广内容直接剔除。

**Apify 成本**：每款游戏每次运行约 0.045 美元（小红书每个搜索词最少返回 20 条）。4 款游戏每 2 天跑一次，每月约 2.7 美元，在免费版每月 5 美元的额度内。如果改成每天跑，或者再加游戏，需要升级付费版。

B 站接口偶尔会触发风控（-352），这时该来源本轮跳过，状态栏会注明，其他来源照常采集。

## 分工

| 环节 | 谁负责 | 做什么 |
| --- | --- | --- |
| 核验 | 规则 + 大模型 | 由模型说明“这是什么事”，列出事实说法，联网逐条核对（DeepSeek、Claude 支持联网）。只拿同一款游戏的其他热点做交叉比对。规则兜底：没有来源链接不算证实；有未证实的说法就不能判可信；与来源矛盾的判为不实 |
| 匹配 | 大模型 + 规则 | 对照这款游戏的设定（受众、调性、禁忌）打 0–100 分，70 分起达标。同时拆解爆点：为什么火、火的形式、可借用的元素、还能热多久。存疑热点跳过这一步。活动已经结束也可以是热点，比如告别、回顾 |
| 生成 | 大模型 + 规则 | 每条达标热点出 2 版抖音脚本，每版必须借用一个爆点元素。规则检查：30–60 秒；分段首尾相接；5 秒内开场钩子；口播语速；2–5 个话题标签，且必须含这款游戏的标签；限制词。不通过就带着错误重写一次 |
| 审核 | 运营 | 复核存疑热点、确认选题、修改脚本、按原因驳回、确认终稿。每一步都记录操作人和时间 |

AI 结果按热点缓存在 SQLite（`analyses` 表），每条只分析一次。`rules.json` 里的 `ai_since` 是 AI 分析起始时间：在它之前就已采到的热点（积压）不再自动分析，页面上标为“积压热点”，由人工核对；之后新出现的热点照常自动分析。修改提示词或游戏设定后，改 `pipeline.py` 里的 `VERSION`，所有热点会重新分析。

## 两种运行方式

- **团队服务（推荐）**：`python serve.py`。审核状态、驳回原因和操作记录存在服务端，多人共享，两人同时修改时会检测冲突。详见 [Local.md](Local.md)。
- **GitHub Pages 静态站**：GitHub Actions 每小时采集免费来源、每 2 天加跑一次 Apify，然后发布快照。静态站不能保存共享状态，所以审核只存在访问者自己的浏览器里，只适合演示。

## 配置模型

在仓库 Settings → Secrets and variables → Actions 中配置下面任意一个 Secret；团队服务则设置同名环境变量：

- `DEEPSEEK_API_KEY`（当前选用）：默认模型 `deepseek-flash`，核验时使用 DeepSeek 自带的联网搜索（搜索本身不收费，只收 token 费）。需要先在 platform.deepseek.com 充值
- `ANTHROPIC_API_KEY`：使用 Claude，默认 `claude-opus-5-5`，核验时联网检索
- `GEMINI_API_KEY`（免费可用）：在 Google AI Studio 申请，默认模型 `gemini-3.5-flash-lite`。免费档没有 Google 搜索功能，所以不联网核验，事实说法转人工复核；另外，免费档的数据会被 Google 用于改进产品
- `DASHSCOPE_API_KEY`（通义）或 `MOONSHOT_API_KEY`（Kimi）：可以完成匹配和生成，但不联网，内容里的事实说法会转人工复核
- `ARK_API_KEY`（豆包）或 `OPENAI_API_KEY`：还需在 Variables 中设置 `LLM_MODEL`
- 其他兼容 OpenAI 的接口：Secret `LLM_API_KEY`，加上 Variables `LLM_BASE_URL` 和 `LLM_MODEL`

未配置模型时，系统照常采集，审核退回纯人工流程。
